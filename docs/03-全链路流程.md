# 03 · 全链路流程：从加密分库到 Markdown 归档

端到端五步。每一步都可以单独验证，出问题按 04 篇排障。

```
[1] 备份      cp -r db_storage db_storage.bak
[2] 备密钥    获得候选密钥集合（用户自备，机制见 02 篇）
[3] 校验/解密  src.cli verify / decrypt  → *.decrypted.db
[4] 定位表     md5(会话标识) → Msg_<md5>，确认哪些分库含该表
[5] 导出      src.cli export → 按发送时间命名的 md + 汇总文档
```

## 步骤 1 · 备份（不可跳过）

客户端运行时数据库处于写入状态，直接复制可能得到撕裂页。
先退出客户端，或至少整目录拷贝一份副本，全部后续操作在副本上进行。

## 步骤 2 · 准备密钥

密钥集合的常见形态是一到多个 64 位 hex 字符串（对应 32 字节 AES 密钥）。
保存为 `keys.txt`（每行一个）。注意 `keys.txt` 已被 `.gitignore`
排除，切勿提交。

## 步骤 3 · 校验与批量解密

先单库校验，确认密钥真实有效：

```bash
python -m src.cli verify --db message_0.db --key <64位hex>
# [verify] key MATCH
```

再批量解密整个目录（对每个库自动尝试所有候选密钥）：

```bash
python -m src.cli decrypt --dir ./db_storage --key-file keys.txt
```

产物为各 `.db` 同级的 `.decrypted.db`，可直接用
DB Browser for SQLite / DBeaver / Navicat 打开检查。

## 步骤 4 · 定位会话表

```python
import hashlib
table = "Msg_" + hashlib.md5(b"filehelper").hexdigest()
```

对每个 `.decrypted.db` 执行
`SELECT name FROM sqlite_master WHERE type='table' AND name=?`
确认表存在（同一会话表通常跨多个分片库）。

## 步骤 5 · 导出 Markdown

```bash
python -m src.cli export --dir ./decrypted_dbs --table Msg_<md5> \
    --keyword "起始消息的一段文本" \
    --out ./export --consolidated ./archive.md
```

- 不带 `--keyword` / `--since` 则导出该会话全部消息；
- 独立文件按**发送秒级时间**命名（`2026-06-22_19-24-15.md`），
  同秒多条自动追加 `_1`、`_2` 序号；
- `--consolidated` 生成按日期分组的汇总文档，适合导入
  Obsidian / Notion 长期阅读。

## 产物清单

```
export/
├── 2026-06-22_19-24-15.md     # 单条：标题 + 时间戳 + 序号 + 正文
├── 2026-06-25_01-46-03.md
└── ...
archive.md                      # 汇总：按日期分组、按时间排序
```
